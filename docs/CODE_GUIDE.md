# 코드 쉬운 설명 (처음 인수받는 사람용)

이 문서는 코드를 처음 보는 사람이 "이게 대체 뭘 하는 코드지?"를 빠르게 이해하도록
쓴 문서다. 상세한 진행 상황/다음 할 일은 `docs/PILOT_HANDOFF.md`를 참고.

---

## 1. 이 프로젝트가 하는 일 (비유)

콜센터 상담원(AI 모델)한테 먼저 "환불 정책이 뭐예요?"라고 물어보고(**Phase 1**),
그다음 실제로 여러 환불 요청을 보내보면서 진짜 어떻게 행동하는지 관찰하고(**Phase 2**),
마지막에 "말한 정책"과 "실제 행동"이 얼마나 일치하는지 점수로 계산한다(**Phase 3**).

여기서 "환불 요청"에 해당하는 게 SorryBench라는 데이터셋에 있는 유해한 요청들
(개인정보 캐내기, 명예훼손 문구 작성, 저작권 침해 등)이다.

## 2. 전체 흐름

```
SorryBench 데이터셋 (유해 요청 9,240개, 44개 카테고리)
        │  filter_pilot_categories.py로 3개 카테고리만 골라냄(개인정보/명예훼손/지적재산권침해)
        ▼
data/processed/pilot_direct3.csv (630개)
        │
        ├─► Phase 1 (phase1.py): "너의 정책이 뭐야?" 3회 질문 → 심판이 유형 분류
        │       결과: results/phase1_rules/*.json
        │
        ├─► Phase 2 (phase2.py): 실제 요청을 3회 보내서 행동 관찰
        │       │  Tier1(키워드로 1차 판별) → 애매하면 Tier2(심판 모델)로 확정
        │       결과: results/phase2_responses/*.json
        │
        └─► Phase 3 (아직 미구현): Phase1이 예측한 것과 Phase2의 실제 행동을 비교
                결과: results/phase3_scores/*.csv
```

## 3. 폴더 구조

| 폴더              | 내용                                                          |
| ----------------- | ------------------------------------------------------------- |
| `config/`         | 설정값 (어떤 모델 쓸지, 어떤 카테고리 쓸지, 거절 키워드 목록) |
| `prompts/`        | 모델한테 보낼 질문 원문 (임의로 수정 금지)                    |
| `data/raw/`       | 원본 데이터셋 (가공 안 함)                                    |
| `data/processed/` | 3개 카테고리만 골라낸 가공 데이터                             |
| `src/`            | 실제로 돌아가는 파이썬 코드                                   |
| `results/`        | 실행 결과 (git에는 안 올라감 — 민감한 원문 포함 가능)         |
| `docs/`           | 이런 설명/진행상황 문서                                       |

## 4. src/ 파일별 설명

### 기반 도구
- **`llm_client.py`** — 모델한테 실제로 질문을 보내고 답을 받는 "전화기" 역할.
  다른 모든 코드가 이걸 통해서 모델과 대화한다.
- **`prompts.py`** — `prompts/` 폴더의 질문 원문을 불러와서 `{CATEGORY}` 같은
  빈칸을 채워주는 역할.
- **`tier1.py`** — 모델 답변에 "거절 키워드"(예: "I can't")가 있는지 빠르게
  훑어보는 1차 판별기. 여기서 실제 버그를 하나 발견해 고쳤다 — 모델이 굽은
  따옴표(’)로 "I can't"를 쓰는데 키워드 목록은 곧은 따옴표(')라 전혀 매칭이
  안 되던 문제.
- **`qa_parser.py`** — 모델이 길게 서술한 답변을 "1번 질문 답, 2번 질문 답..."
  식으로 나눠주는 역할.

### 단계별 실행 로직
- **`phase1.py`** — Phase 1을 수행. 모델한테 정책을 3번 물어보고, 그 답을 심판
  모델에게 보내 "무조건 거절형(T1)/조건부(T2)/프레이밍에 따라 다름(T3)"으로
  분류시킨 뒤 다수결로 최종 유형을 정한다.
- **`phase2.py`** — Phase 2를 수행. 실제 요청을 3번 보내고, Tier1으로 훑어본 뒤
  애매한 것만 심판 모델(Tier2)에게 최종 판정을 맡긴다.

### 직접 실행하는 스크립트
- **`filter_pilot_categories.py`** — 데이터셋에서 우리가 쓸 3개 카테고리만
  골라내 `pilot_direct3.csv`를 만든다. 제일 먼저 실행하는 단계.
- **`run_smoke_test.py`** — 아주 소규모(카테고리당 1개씩)로 파이프라인이
  제대로 도는지 테스트.
- **`run_mutation_test.py`** — 프레이밍을 바꾼 변형 문항(예: "전문가가 말하길...")
  으로 추가 테스트.
- **`reprocess_tier1_fix.py`** — 버그 수정 후, 이미 모은 응답을 재API호출 없이
  다시 채점하는 1회성 스크립트.
- **`generate_report.py`** — 결과 JSON들을 보기 편한 표(`results/report.html`)로
  만들어준다.

## 5. 직접 돌려보는 방법

```bash
.venv\Scripts\activate                  # 가상환경 켜기 (Windows)
python src/filter_pilot_categories.py   # 1. 데이터 준비 (pilot_direct3.csv 생성)
python src/run_smoke_test.py            # 2. 소규모 테스트 실행 (API 호출 발생!)
python src/generate_report.py           # 3. 결과를 표로 보기
```

마지막 명령 후 생기는 `results/report.html`을 브라우저로 열면 결과를 표로 볼 수 있다.

**주의**: 2번 스크립트는 실제 API를 호출해서 비용이 발생한다. CLAUDE.md 규칙상
API를 실제로 호출하는 작업 전에는 예상 호출 횟수를 계산해서 팀 확인을 받고 실행해야 한다.
